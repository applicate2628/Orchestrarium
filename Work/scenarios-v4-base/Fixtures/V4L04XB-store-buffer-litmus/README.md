# V4L04XB-store-buffer-litmus

Brutal-difficulty discrimination pilot, base form. Lane `L04X`.

A reachability-classification gauntlet over two fully-pinned store-buffer
machines: `SB-A` (unbounded FIFO buffer, store-to-load forwarding) and
`SB-B` (capacity-two FIFO buffer with forced oldest write-back, no
forwarding). The candidate classifies 32 observations across
16 litmus programs into `both` / `a-only` / `b-only` / `neither`,
lists the divergent programs, and commits an equivalence verdict.

Difficulty is intrinsic, not informational: the visible spec is complete
and a perfect reasoner scores 100, but correct classification requires
either flawless operational reasoning over all interleavings or a
faithfully implemented exhaustive enumerator of BOTH custom semantics —
with no shipped answers to debug against. The ground truth is generated by
`oracle/ground-truth/reproducer/` (exhaustive BFS over the full
configuration space; both reachable and unreachable verdicts are
machine-checked) and never hand-asserted.

- Visible inputs: `inputs/` (task, output schema, machine spec, programs).
- Candidate artifact: `candidate/litmus-answer.json`.
- Hidden oracle: `oracle/rubric.json` scored by the frozen
  `Tooling/v4_rubric` adapter via `verifiers/score.py`.
- Probes: `oracle/probes/` (reference, competent, vacuous, decoy,
  alternate-valid, paraphrase, overclaim).
- Reproducer: `oracle/ground-truth/reproducer/` (regenerates every derived
  artifact byte-identically; `test_machines.py` validates the enumerator
  against the documented classic-TSO litmus corpus and an independent
  sequential-consistency oracle).

Identity keys are the visible observation IDs (`P01-O1` ..), the visible
program IDs (`P01` ..), and the closed class vocabulary from `task.md`.
`oracle/ground-truth/index.json` records the per-observation derivation.
