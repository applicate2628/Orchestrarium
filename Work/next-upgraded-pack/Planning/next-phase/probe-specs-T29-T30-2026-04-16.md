## Probe `T29`

| Field | Spec |
|---|---|
| Test ID | `T29` |
| Working name | `toolchain false-root ambiguity` |
| Primary line | `L08 worker.toolchain-root-ownership` |
| Secondary line value | supports sharper interpretation of `L10` when ownership continuity is involved |
| Core pressure | multiple plausible roots, one true owner, explicit anti-hardcode verification |

### `T29` intended fixture shape

| Element | Requirement |
|---|---|
| true owner | one real root or toolchain seam must own the fix |
| decoy roots | at least two plausible but wrong roots should exist |
| broken state | the starting state should fail in a way that can be superficially patched in the wrong root |
| control pass | the correct root must pass both the functional verifier and the owner verifier |
| anti-cheat | verifier should reject exact-path shortcuts and direct root-string hardcoding where feasible |

## Probe `T30`

| Field | Spec |
|---|---|
| Test ID | `T30` |
| Working name | `static UI wrong-file attraction` |
| Primary lines | `L05 review.ui-static`, `L09 worker.ui-implementation` |
| Core pressure | distractor components and nearby files that look editable but are not the real owner |
| Modality rule | non-browser by default |

### `T30` intended fixture shape

| Element | Requirement |
|---|---|
| real owner seam | one real UI owner must exist for the intended fix |
| distractors | nearby files, components, or assets should look tempting but be wrong |
| broken state | visible static UI defect that can be misinterpreted from nearby context |
| control pass | correct seam edit passes the verifier and preserves style consistency |
| anti-drift | wrong-file local cleanup should fail if it leaves the real defect or damages nearby surfaces |

## Shared acceptance criteria for `T29` and `T30`

| Requirement | Meaning |
|---|---|
| broken-state evidence | each probe starts from a real failing state |
| control-pass evidence | each probe has a validated correct state |
| owner verification | passing requires the real owner seam |
| anti-hardcode | brittle exact-path fixes should not pass |
| anti-drift | unrelated visible or contract surfaces should stay intact |

## Gate to fixture build

These probe specs are implementation-ready when:

1. their intended fixture shapes are concrete enough to build in `Fixtures/`
2. no unresolved line-target ambiguity remains
3. they can be validated locally without browser dependence
