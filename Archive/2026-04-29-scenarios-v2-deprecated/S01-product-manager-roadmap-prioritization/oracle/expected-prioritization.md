# Expected Prioritization

## Preferred roadmap order

### Priority 1 - Wave 4 materialization and gates

This is the strongest first priority because it closes the missing roadmap-owner surface and lands
the accepted fourth-wave scope as real benchmark evidence. It also establishes the integrated gate
path that every later rerun or publication claim depends on.

### Priority 2 - Final coverage wave and rerun readiness

This is the strongest second priority because the single clean rerun window should be spent only
after the remaining semantic gaps are closed. The roadmap should preserve a coherent story:
complete the admitted waves, then spend rerun and publication effort on a role set that is no
longer knowingly incomplete.

## Why the deferred items lose points

- `Immediate publication rerun` loses points if admitted early because it spends the visible rerun
  budget before the final coverage wave lands.
- `Browser overlay expansion` loses points because it adds runtime complexity without helping the
  launch-critical completeness and credibility constraints.
- `Archive and README cleanup` can be a small carryalong later, but it is not strong enough to
  replace either of the first two roadmap slots.

## Admissible nuance

A strong package may note that archive cleanup can piggyback only if it does not consume its own
review cycle. That nuance does not change the top-two ordering.
