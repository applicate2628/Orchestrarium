# Report Boundary

The correct output is one UI regression report for a bounded Qt dialog surface.

It must:

- stay findings-first and evidence-backed
- include stable checks plus the seeded regressions
- describe what must be rechecked after a fix lands
- stop short of the implementation patch, QA verdict tables, or unrelated review lanes

It must not:

- prescribe code edits
- introduce acceptance-criteria matrices or bug-registry workflow
- drift into accessibility-specific or UX-specific findings
