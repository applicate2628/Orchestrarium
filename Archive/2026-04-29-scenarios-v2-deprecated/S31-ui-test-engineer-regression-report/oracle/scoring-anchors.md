# Scoring Anchors

Strong reports:

- cite the exact evidence files used
- name the stable checks before or alongside the regressions
- tie each regression to a concrete reviewed file and observed state
- keep remediation at the recheck level instead of writing the patch
- end with `REVISE`

Weak reports:

- read like a generic QA template
- omit the stable controls and treat the dialog as universally broken
- drift into accessibility, UX, or implementation commentary
- describe visual problems without anchoring them to theme or scaling evidence
