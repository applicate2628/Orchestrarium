# Research Memo

## Scope

Large ongoing research item covering:

- provider-native MCP inheritance and child-scoping behavior on `Codex`, `Claude`, and `Gemini`
- local MCP inventory and operational usefulness by role
- benchmark-task design for cross-provider and cross-role replay
- future `agents-mode` recommendation logic informed by benchmark evidence

## Accepted findings so far

### 1. Parent-to-child MCP inheritance risk is real

| Provider | Accepted finding |
|---|---|
| `Codex` | Custom agents may define `mcp_servers`; when omitted, inherited parent surface is the practical risk to control. |
| `Claude` | Subagents inherit parent tool surface by default; child-scoped `mcpServers` and tool lists are available. |
| `Gemini` | Subagents inherit parent tools when `tools` are omitted; child-scoped `mcpServers` and explicit tools are available. |

### 2. Direct external parent CLI runs may still orchestrate native internal children

| Provider | Accepted finding |
|---|---|
| `Codex` | A direct Codex CLI parent may use native subagents; nested depth is bounded by Codex settings. |
| `Claude` | A direct Claude CLI parent may run child agents via native subagent surfaces, including headless `--agent` / `--agents`. |
| `Gemini` | A direct Gemini CLI parent may delegate to native subagents; subagents themselves do not continue spawning further subagents. |

### 3. Current local MCP-inventory snapshots matter

| Provider | Accepted finding |
|---|---|
| `Codex` | Current global config contains a broad configured MCP inventory; enabled subset includes `context7`, `fetch`, `memory`, `sequential-thinking`, `serena`. |
| `Claude` | Current live list shows `context7`, `telegram`, `serena`; cache contains additional MCP-capable plugin packages that are not automatically part of the active surface. |
| `Gemini` | Current `gemini mcp list` is empty; extension surfaces exist, but user-level configured MCP state is much thinner than Codex. |

### 4. Must-have direction is converging

| Category | Accepted direction |
|---|---|
| universal core | `github`, `serena`, `context7`, `fetch` are leading candidates |
| UI verification | `playwright` remains a likely must-have when UI work exists |
| stack-specific depth | language MCPs should be added by dominant stack, not globally all at once |
| exclusions | personal MCPs such as `raindrop` and `telegram` should stay outside system recommendations |
