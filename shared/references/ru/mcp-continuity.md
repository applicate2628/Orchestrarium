# Непрерывность MCP

Непрерывность Model Context Protocol (MCP) восстанавливает руководство по поиску инструментов при старте сессии или компакции. Напоминания о ходе и параллельной работе поддерживают непрерывность workflow; Claude также выдаёт неблокирующее advisory для квалифицирующих решений о навигации по коду.

## Общее семантическое ядро

Один модуль политики без зависимостей, `scripts/universal-hooks/scripts/mcp_continuity_policy.py`, владеет стартовым поиском инструментов, непрерывностью хода и классификатором, используемым адаптером Claude для навигационного поиска:

| Событие | Адаптер | Общее поведение |
| --- | --- | --- |
| `SessionStart` | `mcp-usage-reminder.py` | Возвращает полный текст о поиске и использовании MCP после новой сессии или компакции. |
| `UserPromptSubmit` | `turn-anchor-reminder.py` | Добавляет короткий checkpoint для продолжения активной задачи и готовности к делегированию, не повторяя подсказки по выбору инструментов. |
| Claude `PreToolUse` | `agents/scripts/check-mcp-momentum.py` | Использует общий классификатор поиска для неблокирующего advisory; root force-mode advisory напоминает о действующих обязательных требованиях к использованию MCP. |

Политика допускает ровно `Grep`, `Bash`, `PowerShell`, `shell_command` и `exec_command`. Shell-входы читают `tool_input.command`; `exec_command` читает `tool_input.cmd` и принимает `command` как совместимую форму. Shell-текст считается недоверенными данными: политика токенизирует его и никогда не исполняет.

## Свежесть stateful и индексных MCP

Руководство при старте сессии и постоянные правила использования инструментов
считают изменение репозитория, проекта, ветки, worktree или индексного ввода
причиной считать прежний результат подключённого stateful или индексного MCP
неактуальным. Агент обязан использовать собственную проверку статуса/свежести
этого сервера; если она сообщает об устаревшем или ожидающем состоянии, нужно
выполнить документированную синхронизацию, обновление или переиндексацию,
снова подтвердить свежесть и только затем повторить исходный запрос. Явно
ненормативный пример workflow: для CodeGraph это `status -> sync -> fresh status
-> repeat query`; это имя никогда не выбирает инструмент.

При выборе или смене проекта, либо восстановлении устаревшего состояния, сообщаемая инструментом идентичность проекта/индекса совпадает с выбранным корнем до использования; сообщается об известном пропущенном покрытии вместе
с результатом. Если инструкции конфликтуют с установленным инструментом, до
действия нужно проверить собственные поддерживаемые entrypoint, help и version;
не изобретать и не переисполнять
pipeline этого инструмента. Перед тем как считать вывод графа о вызовах, зависимостях или радиусе влияния точным доказательством для решения, нужно сопоставить квалифицированный символ и, где применимо, объявляющий тип/файл с запрошенной целью; различать прямые вызовы, callback/косвенную достижимость и нечёткие предложения. Неоднозначные/несопоставленные строки требуют проверки исходника; не объявлять их точными.

Это правило основано на способности, а не на реестре провайдеров или серверов:
MCP без сохраняемого состояния или live MCP не требует refresh. Неудачное обновление сообщается
явно, а устаревший вывод не представляется как актуальный. Проверка при выборе,
смене и восстановлении не является проверкой version при каждом вызове, не
требует нового vendor API и никогда не предписывает автоматический deep/LLM build.

## Классификация навигации

Momentum-предупреждение распознаёт навигационные паттерны в исходниках, а не любой текстовый поиск:

- `rg`, `ag` и `ack` рекурсивны по умолчанию; `grep` квалифицируется только с рекурсивной опцией.
- Квалифицируются области исходников, ориентированные на исходники селекторы, паттерны символов или определений и `rg --files` по области исходников.
- Чтение известного файла не квалифицируется только из-за использования поисковой команды.
- Адаптер передаёт необработанный `cwd` из конверта хука; только политика проверяет, что он абсолютный, и находит ближайшего предка, содержащего каталог или файл `.git`.
- Явная область освобождается только тогда, когда лексическая нормализация от этого проверенного `cwd` делает её равной `<repo>/work-items`, `<repo>/.reports`, `<repo>/.plans` или `<repo>/.scratch` либо их потомком, ограниченным компонентами пути. Совпадающий сегмент пути на любой другой глубине освобождения не даёт.
- Освобождение сохраняет молчание вызова только тогда, когда у него есть хотя бы одна явная область и каждая явная область имеет корневое освобождение. Смешанная, внешняя, некорректная или неразрешимая область предотвращает освобождение; отсутствующий или некорректный `cwd` либо отсутствующий маркер репозитория освобождения не дают, и подстановки рабочего каталога процесса нет.
- Нормализация области лексическая: она не требует существования цели, не раскрывает shell-синтаксис и не следует по символическим ссылкам или junction. Команда смены каталога делает следующую относительную область неразрешимой; следующая абсолютная область остаётся классифицируемой.

Точное освобождение task-memory намеренно узкое. Оно не создаёт общего освобождения для документации или произвольных путей репозитория.

## Граница доставки и приватности

Общий классификатор не определяет соблюдение требований или разрешение на
инструмент. Codex использует стартовые подсказки и напоминания о workflow без
регистрации поискового аудита. Claude выдаёт неблокирующее advisory при
`mcpMode: auto`, для конвертов делегированных агентов и для корневого диалога
при эффективном `mcpMode: force`. При действующем force-требовании обязательны
runtime tool discovery и соответствующая схема инструмента, а также применение
подходящего MCP с соблюдением существующих ограничений для альтернативных
путей; по-прежнему нужны проверки выбранного корня и актуальности данных.
Runtime discovery — единственный источник доступности. Advisory не определяет
соблюдение требований, не выдаёт разрешение и не отменяет отказ хоста.
Неразрешённый режим выдаёт стабильное диагностическое advisory. Все пути
fail-open на уровне процесса и не изменяют сохраняемое состояние.

Универсальная политика не читает домашнюю MCP-конфигурацию, не выводит
доступность из настроенных имён и не выбирает инструмент по реестру имён.
Квалифицирующие advisory-пути выдают один общий checkpoint runtime discovery.
Имена инструментов в документации являются явно ненормативными примерами и
никогда не участвуют в логике выбора.

Advisory-пути влияют на следующее действие модели, но не доказывают исполнение указания. Turn anchor отражает общее правило **Primary-task continuity and side work**: краткий ответ сразу, своевременное делегирование существенной допущенной дополнительной работы и продолжение готового основного действия без ожидания её результата. Синтетический тест payload доказывает только доставку этого контекста. Доставка в оба пакета и наблюдение текущего хода не доказывают универсальное будущее поведение модели; обязательного испытания модели другого провайдера нет. Advisory Claude в корневом force-режиме не определяет соблюдение требований, не доказывает успех MCP и не покрывает инструменты вне matcher. Идентичность установленного исходнику варианта и поведение в длинном ходе требуют отдельной post-install проверки.

Специфичные для провайдера конверты событий, регистрация matcher и установленные пути описаны в [дополнении Codex](../../../references-codex/ru/mcp-continuity.md) и [дополнении Claude Code](../../../references-claude/ru/mcp-continuity.md).

## Термины и сокращения

- `MCP`: Model Context Protocol, интерфейс, через который доступны подключённые инструменты и ресурсы.
