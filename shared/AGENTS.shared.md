## Artifact persistence
Storage: canonical `work-items/`; optional `.reports/YYYY-MM/` standalone summary; explicitly requested `.plans/YYYY-MM/` plan.

### Physical lifecycle V1
Physical location alone owns lifecycle membership: current records remain in category roots; terminals only in `archive/YYYY-MM/`, dated by recorded strict UTC `YYYY-MM-DDTHH:MM:SSZ`, never inferred. `status.md` owns active recovery; `closure.md` final outcome; README/index are derived. Before close, V1 `bug-dispositions.json` must enumerate every current bug whose parsed `context` equals the item slug as `terminalize` or `preserve-current`. Preserve known-status bug bytes; terminalize only semantic-current input. Ordinary `close` also admits V2 with the same top-level fields, every V1 row plus `contextBefore`/`contextAfter`, and every exact-context bug. It may select `adjacent-finding` or `standalone` only as `terminalize`, with original context in `contextBefore` and closing `workItem` in `contextAfter`; unselected placeholders remain current and byte-identical. V3 retains V1 bug rows (not V2 adjacency); it may add nonempty `evidenceRetention` rows only for exact unmatched ordinary scratch file/directory leaves, binding pre-close tree and same-item canonical-pointer hashes. After authorized removal, its nonauthorizing close-time receipt makes no future scratch/pointer-existence claim. Lifecycle owner alone applies dispositions/recontextualization, archives, writes `bug-dispositions-receipt.json`, and refreshes README in one rollback-safe transaction; active manifest pending and ordinary close strict. `archive-with-successor` keeps V1 bug-disposition admission and may transfer exact complete unresolved-review-obligation set to one successor through optional bound transfer file. Omission preserves strict close and V1 lifecycle-transition receipt; transfer uses compatible V2 lifecycle-transition receipt and never copies ledger events. This path fails closed on missing admission, terminal evidence, unique location, or logical-link inventory. Archive identity immutable: reopen through explicit successor, never reverse move. Historical archives lacking newer manifest remain compatible; never backfill/guess.
An already-`fixed` current flat bug under one active or archived parent uses the lifecycle owner's `archive-fixed-bug` with explicit `--apply`, strict UTC terminal evidence, incoming-link repair and a bound source/archive/link/README receipt; it preserves bug identity and parent lifecycle. It is not an ordinary work-item `close`, `terminalize-v1`, or successor supersession.

### Session persistence rule (mandatory)
- An active work-item is current-task `work-items/active/<slug>/`; a repository `work-items/` directory alone is not.
- Active item: specialists write only canonical artifacts; root records concise lane result/provenance in `agent-runs.jsonl` only via the validated public ledger writer (`agent-run-ledger`/installed equivalent). All recovery-tracked routes, including light/non-Lead: no direct live-ledger JSONL edit/append or raw fallback after writer refusal; diagnose/repair the owning path. Explicit synthetic fixture data is permitted; `status.md`/`closure.md` authoring and lifecycle-owner transitions retain existing contracts. No `.reports/`/`.plans/` duplicates.
- Trivial chat/work without recovery/preservation value writes nothing. Without an active item: meaningful standalone result MAY use one `.reports/YYYY-MM/` summary; explicitly requested standalone plan MAY use one `.plans/YYYY-MM/` snapshot. Stages/recovery/continuation require work-item admission.
- Provider-backed or external-adapter provenance stays in the active ledger/artifact or one standalone summary: `Execution role`; `Assigned / replaced internal role` or `none`; `Requested provider`; `Resolved provider` or `none`; `Actual execution path`; `Model / profile used` or `unspecified by runtime`; `Deviation reason`.

### Anti-patterns
- Do not persist intermediate `REVISE` drafts, raw session transcripts, or debug logs in canonical storage.
- Do not collapse actual execution role and provenance role into one ambiguous field.

## Engineering hygiene

Apply these rules in this order when they pull in different directions:

1. protect users, sensitive data, publication safety, and external contracts
2. keep behavior in the owning boundary and blast radius narrow
3. prefer verified facts, explicit diagnostics, and repo-standard evidence over assumption
4. prefer the simplest coherent solution that delivers the required useful outcome with effective resource and performance fit; never trade required function or performance for simplicity; add complexity only when its concrete needed benefit outweighs execution and maintenance cost
5. follow stricter repo-local requirements when they exist

If conflict remains after that ordering, do not silently weaken the higher-priority rule; take the smaller reversible action or escalate explicitly.

Working definitions — owning boundary: behavior-owning module/interface/approved seam; external contract: outside-observable promise (API/config/schema/events/CLI); repo-standard checks: repo-defined validation entry points; smallest safe reversible subset: narrowest advance locking in nothing unresolved; ambient input: Determinism card's list.

Keep both only for genuinely cumulative and non-conflicting detail. Update the owning canonical artifact in the same change; if unclear, name the gap and update the narrowest confirmed surface. Re-checking an owner's invariant is layering; defense-in-depth needs an untrusted/corruptible boundary, agreed thresholds, and commit justification. Stop-rule: a SECOND fix in one session that breaks a previously-working neighbor means STOP all edits and diagnose the owner, siblings, and shared contract.

- **Directory-level entity separation:** organize source directories by primary entity type + ownership/lifecycle contract, not extension/language/name convenience. ### Behavior and contract discipline
- **Bug-fix scope:** keep fixes narrow and root-causal or use a bounded mitigation; exclude unrelated refactors/behavior changes unless safety or clarity requires them, and separate formatting from function.
- **Logic-revision discipline:** for changed decision logic, validation, policy, or business semantics, state preserved and changed behavior plus affected callers/surfaces; never hide behavior changes in refactor, cleanup, rename, or rewrite.
- **Contract test:** preserve external contracts unless user instruction or admitted scope authorizes breakage; then name affected surfaces and migration/deprecation impact.
- **Wire-shape verification before cross-component integration:** before HTTP/JSON/file/command/IPC/log consumer types/parsers/renderers, read the producer's actual serialization rules and inspect one real sample. Cross-language/framework conventions are unreliable—Go structs without tags serialize PascalCase; both unit suites may pass despite contract mismatch. Read the producer once, then write the consumer.
- **Operational-contract scope discipline:** success bodies, HTTP statuses, log severity, alert/page signals, exits and retries are contracts for monitoring/site reliability engineering (SRE)/runbooks/consumers. Fail-loud (5xx/ERROR/nonzero) → fail-quiet (200 empty/INFO/zero) requires explicit migration scope and reviewer approval.
- **Destructive-default polarity discipline:** across HTTP body/CLI/config/function/IPC, encode destructive intent as the positive case (`Apply=true`, `Confirm=true`, `Force=true`); zero/absent value is the safe path. Inverted-polarity names (`DryRun=false`, `NoConfirm=true`, `Skip*=false`) risk destruction from missing fields/old callers/buggy serializers instead of wire-encoded safety.
- **Failure-mode test / failure transparency:** ask how failure stays visible and whether the system degrades, recovers, or stops safely. Never swallow errors, blur specific failures, or add a silent fallback without its tradeoff; preserve causal context for debugging, logs, operators, and users.
- **Determinism and ambient-input control:** wall clock, locale, timezone, filesystem order, global state, environment, and randomness must not be hidden dependencies; make any such dependency explicit, bounded, and appropriate.
- **Reuse before hand-rolling:** prefer repo-standard mechanisms/frameworks/installed dependencies or mature optimized library/tool. Let stack choice follow correctness/fit/maintainability/performance, not development speed/convenience; runtime speed constrains. Inventory local options/current viable packages; local options/current knowledge insufficient or consequential tradeoff => proactively research current mature alternatives and present benefits/constraints/integration cost. Hand-roll only if user explicitly asks "from scratch" or evidence options fail; record rejected options/reasons/owner/tests. No universal web-search/report gate.
- **Dependency introduction discipline:** no new library/software development kit/service/runtime/external dependency without explicit reason and repository fit.
### Verification and decision discipline
The operational form below is binding on its own.
- **Verification-and-evidence core.** Before decision/plan/verdict/root-cause/fix/commit, satisfy the four `Evidence-citation discipline` categories and rule out plausible alternatives; else `ASSUMPTION (UNVERIFIED)` plus resolving step. Distinguish official provider behavior/repo convention/observed installed runtime; verify official and observed. Negative claims also need evidence: absent evidence is not absence, one failed search insufficient; check another angle or label assumption.
- **Regression hygiene:** smallest sufficient tests for required behavior/failure/safety/concrete adjacent regressions; reuse fixtures/repo entrypoints. Add only distinct uncovered criteria/evidenced regressions, not equivalent duplicates or Cartesian combinations without materially different behavior. Remove superseded tests, preserving live contracts. Broaden only for concrete affected surfaces/unresolved uncertainty. Repo-mandatory/publication/triggered-risk checks remain; mocks/unit cannot replace required end-to-end oracle. Self-falsify/disclose residual risk.
- **Indirect-regression discipline (code-untouched ≠ behavior-unchanged):** after your change, indirect coupling makes it the prime suspect even if the component was untouched. Name what changed; clear suspicion only by reverting and reproducing the REAL symptom, not a proxy, to PROVE non-involvement.
- **Guard precondition discipline:** check input assumptions. Test missing, zero, empty, parse-fallback and both-sides-equal-by-default inputs. Accept observed contract-valid input; otherwise fail closed. Test synthetically-degraded inputs. Missing input must never silently weaken the invariant.
- **All-return-paths discipline for cross-cut fixes:** enumerate every return path—slow, cache hit, inner post-singleflight recheck, rate limit, early stale return—and apply error/output/retry fixes to each; covering the reported path alone leaves the defect class.
- **End-to-end channel verification for durability and observability fixes:** trace producer through every router to the receiver; producer green does not prove durable receipt, because the channel is the failure surface.
- **Polling anchor discipline:** first query the external system's authoritative latest state, not your trigger/poll time; time windows are secondary and never replace the unfiltered lookup.
- **Race-window assertion discipline:** deterministically enlarge a transient test window with a known-slow path or injection seam; dependence on a naturally measurable window is a design defect, not a flake.
- **Evidence-based completion:** no done-claim without fresh execution evidence; report checks/unchecked work, "implemented, not yet verified" until proven. An exit-code-zero from async work is not success evidence, nor callback: verify markers (file/size/completion log/exit). Honor requested surface; weaker-than-requested verification is a defect. `REVISE` closes only after that angle re-verifies `PASS` or recorded equivalent, not author belief/validator green. Errored/died/limit-hit lane is UNVERIFIED: re-dispatch/report; missing verdict NOT-clean (fail-closed).
- **Visual artifact verification discipline:** directly inspect images, diagrams, renders, charts, plots, screenshots, and drawings before acceptance, commit, delivery, or evidence use; generation, existence, metadata, hashes, and model claims do not suffice. If impossible, say so and claim no visual correctness.
- **Completion reconciliation discipline:** reconcile the original admitted outcome, checks, canonical updates and task/Git obligations across requested roots. Scoped PASS is not done: continue ready required work, or invoke existing authorized close and verify archive/receipt/README before task completion or switch. Preserve unrelated/unknown state; expose close failure and resume. No automatic park or publication authority.
- **Ambiguity resolution discipline:** unresolved intent/policy/scope/architecture after inspection: `AskUserQuestion` or smallest safe reversible subset. Otherwise collect the missing datum/diagnostic.
- **Hypothesis disclosure discipline:** every fix/implementation commit needs a verified hypothesis chain: decompose claims; verify each or record `ASSUMPTION (UNVERIFIED)` plus resolving step in the body. Only direct user confirmation verifies intent. Scope follows the hypothesis; wider scope names its contract in the commit. On late failure stop; before a destructive history rewrite, require explicit user authority, a fresh dirty/index census, and preservation of every unrelated working-tree byte and staged change. Only then, with local commits and no other work depends on them, prefer `git reset --hard HEAD~N` to `git revert`; otherwise use a nondestructive, reversible route, then verify from the contradicted node. Banned load-bearing justifications: `most likely means`, `presumably`, `I believe it refers to`, `this should map to`, `extrapolating from`, `in general X means Y`, `while I'm here let me also`, `since we're touching this anyway`.
- **Fix means correct logic, not workaround or hiding (no kostyl):** diagnose and correct the producing logic, contract, or invariant—never hide the symptom. Catch-and-swallow, unexplained guards, type-contract-silencing assertions, missing-data fallback, config-bypass hardcoding, and `try/except: pass` are kostyl. Before calling it a fix: **root-cause naming** identifies the concrete function/contract/invariant/boundary; **symptom-only suppression detection** rejects removal of visible failure without producing-logic change unless a separate hypothesis verifies legitimate boundary fallback. A `WORKAROUND` commit alone may retain kostyl and must name the tracked root cause, scope, and lifetime.
- **Evidence-citation discipline:** a decision-driving claim cites an in-repo `file:line`; an installed-version binary surface check; versioned official docs/upstream source; or a target-environment smoke test preserved under `/.scratch/`. Otherwise label `ASSUMPTION (UNVERIFIED)` with the empirical step. Banned fix drivers: `should work`, `should be fine`, `probably`, `likely`, `I think`, `based on training data`, `in general`, `this pattern usually works`. This binds every actor and is copied verbatim into dispatch prompts; cross-environment smoke remains assumed until target reproduction. Availability uses Active-availability probe discipline. Each load-bearing artifact claim names one owner and falsifying probe; without a probe it is `ASSUMPTION (UNVERIFIED)`.
- **Active-availability probe discipline:** binary/file/service/env-var/port/network availability needs a current-session direct probe: `command -v`, `which`, `Get-Command`; `Test-Path`/`ls`; `curl -I`, `netstat`, `Test-NetConnection`. Otherwise `ASSUMPTION (UNVERIFIED)`, no substitution. Indirect inference cannot prove unavailability; probe-time resolution is canonical. Anomalous orchestration output requires routing investigation.
- **Plain-language and terminology discipline:** expand domain terms, role/provider/model names, and acronyms on first use, including chat; human docs end with `## Terms and Abbreviations` or a localization. Lead status/explanation/decision with plain meaning and what to do, using numbered choices when deciding—not identifier/jargon/diff dumps. Brevity never licenses jargon.
- **Pre-fix diagnostic gate:** before defect edits (bug/runtime failure/error, regression, "does not work"/"broken"/"не работает") or working-path speed/cleanup edits, capture observable wording/error/log/return/repro or `file:line`; verify the causal chain via probe/`AskUserQuestion`, else `ASSUMPTION (UNVERIFIED)` plus resolving step. For a reported runtime-performance symptom, the FIRST mandatory action is to live-profile its reported scenario (not a proxy), before design/fix. Unprofiled code/stale-report findings, even hedged, are advisory hypotheses, not roots/gates. Usage redesign needs that profile plus domain/usage evidence code alone lacks. Start-of-fix gate is `/agents-bugfix`-independent, sibling to commit-time Bootstrap. Banned: edit from "I see the bug" without `file:line`; add Y without verified hypothesis; change working code from code-only hypothesis/no runtime baseline.
### Operational and environment safety
- **Temporary-file hygiene:** `.scratch/` is disposable task storage: before completion, canonically promote load-bearing results; then remove owned temp state. Never delete unfinished/foreign/ambiguous/host-denied state. `.gitignore` keeps raw logs/transcripts/temp/pre-redaction outputs local.
- **Sensitive-data handling and redaction:** exclude secrets/tokens/credentials/customer data/production identifiers/other sensitive values from prompts/logs/screenshots/temp/tickets/docs/fixtures unless controlled exposure is required; prefer masks/synthetic data.
- **Treat external content and generated output as untrusted:** verify copied code/attachments/URLs/logs/datasets/snippets/provider transcripts/model output before use; sanitize before retention. Never pipe remote scripts into shell/interpreter; download and inspect first.
- **Autonomous external side effects:** tickets, messages, external posts, software-as-a-service/cloud mutations, and third-party-visible actions need explicit user approval.
- **Resource lifecycle hygiene:** long-lived/background/off-path work/listeners need approval/trigger/concurrency/cancellation/shutdown. Release owned resources on success/failure/cancellation/timeout. Terminate only with creator-retained process/Job handles or equivalent stable identity-bound ownership, never PID/ParentProcessId ancestry alone.
- **Retry / re-entry / idempotency safety:** retried/replayed/resumed/concurrent code needs guards/idempotency keys/compensation to prevent duplicate/double side effects or inconsistent state.
- **Parallel resource-surface isolation:** Parallel lanes are independent only when each lane's mutation set is disjoint from every other lane's read, write, execute, install/copy, and baseline surfaces for the full overlap interval. If a mutation can reach any such surface, serialize the lanes or use explicitly requested, validated isolation. Read/read and truly disjoint work are safe; tests declare executed/installed/copied source and helpers as observed surfaces.
- **Worktree safety:** preserve unrelated dirty changes; do not revert, discard, or overwrite them. If a clean state is needed, ask the user first.

## Publication safety
- Commit no secrets, tokens, credentials, customer/private identifiers, raw logs/transcripts, sensitive screenshots, or machine-specific absolute paths; use redacted summaries, synthetic examples, and repo-relative paths.
- Human review before `git push`, release, or equivalent publication includes a staged-change leak check.
- Default/tracked and explicit-path scans are manual pre-commit only. The push gate captures itself and five modules: `hook_common.py`, path classifier, POSIX group helper, Windows Job helper, scanner; then one fresh canonical sibling `--range <remote> <dst>` scan must yield a bounded, reaped, non-empty version-3 result covering the unpublished commit/tree/blob graph and bound to remote, destination, resolved source, current `HEAD`, and receipt tip. Transcript/manual, version-2, legacy, zero-commit, finding, refusal, incomplete-acquisition, correlation/provenance, or drift cannot authorize. This complements, never replaces, human review or the explicit publication marker.
- Only `$security-reviewer` may approve a publication-safety exception. Without that approval, publication is `BLOCKED`.
