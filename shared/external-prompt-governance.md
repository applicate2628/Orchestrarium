- **Anti-hardcoding:** do not hardcode machine/user/repo-layout/environment, secret, or policy-owned values when constants, config, parameters, environment variables, or discovery suffice; shared artifacts use repo-relative/documented forms. True invariants, protocol constants, and small algorithm-local literals are valid; state the tradeoff before other hardcoding.
- **No logic duplication / no fix layering:** keep one coherent current truth; do not duplicate decisions or fixes. A clarification that changes a live textual artifact's meaning supersedes its prior wording; history belongs in version control or a decision/closure record. Retain both only for genuinely cumulative and non-conflicting detail. Update the canonical owner in the same change; if unclear, name the gap and update the narrowest confirmed surface. Re-checking the owner's invariant is layering; defense-in-depth requires an untrusted/corruptible boundary, agreed thresholds, and commit justification. If a SECOND same-session fix breaks a working neighbor, STOP edits and diagnose owner, siblings, and shared contract.
- **General-case over local symptoms:** find the correct concept/abstraction level: owner (state/contract/invariant/lifecycle/pipeline/component) and siblings (modes/surfaces/inputs/timing). One cause gets an owner-level general case through its seam and smallest coherent surface, with interfaces/coordination inside it and wider coupling stated. Broad impact is seam suspicion; SOLID is only a pressure test. Commit the preserved/generalized invariant. Require correctness over development speed unless prototype/fastest/throwaway is explicit. Only an explicit user-approved boundary may leave broader cases left untouched, with verified rationale. Banned: "user mentioned only this mode", "visible only here", "fastest patch", "other modes probably do not hit it", "generalize later".
- **Directory-level entity separation:** organize source directories by primary entity type and ownership/lifecycle contract, not extension/language/name convenience. Before add/move, classify owner/invoker lifecycle and input/output contract, side effects, and gate semantics; group only when both match or as one command's platform variants. Otherwise use a canonical directory, typed subdirectory, or recorded exception—never a catch-all. Build output, caches, `__pycache__`, gitignored `.scratch/`, and generated outputs are excluded. Details: `shared/references/repository-source-hygiene.md`.
- **Trash hygiene and archival:** within the admitted surface and `Worktree safety`, remove replaced/superseded/dead files. If uncommitted/session-unrecorded history would be lost, archive it under `archive/`, `legacy/`, or `<dir>/_archive/` with one breadcrumb. Leave no half-finished alternative, dead helper, stale doc, or removal TODO beside live code.
