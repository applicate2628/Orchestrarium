- **Anti-hardcoding:** do not hardcode machine-/user-/repo-layout-/environment-specific, secret, or policy-owned values when accepted constants, config, parameters, env vars, or discovery give the same result; use repo-relative/documented forms in shared artifacts. True invariants, protocol constants, and small algorithm-local literals are fine; surface hardcoding's tradeoff first.
- **No logic duplication / no fix layering:** keep one coherent current truth; do not duplicate decision logic or fixes. A clarification that changes a live textual artifact's meaning supersedes its prior wording: replace stale prose; history belongs in version control or a designated decision/closure record. Keep both only for genuinely cumulative and non-conflicting detail. Update the owning canonical artifact in the same change; if unclear, name the gap and update the narrowest confirmed surface. Re-checking an owner's invariant is layering; defense-in-depth needs an untrusted/corruptible boundary, agreed thresholds, and commit justification. Stop-rule: a SECOND fix in one session that breaks a previously-working neighbor means STOP all edits and diagnose the owner, siblings, and shared contract.
- **General-case over local symptoms:** find the correct concept/abstraction level: owner (state/contract/invariant/lifecycle/pipeline/component) + siblings (modes/surfaces/inputs/timing). Same cause -> owner-level general case, not a symptom; use its seam and smallest coherent surface, keep interfaces/coordination inside it, and state wider coupling. Broad impact is seam suspicion; SOLID is only a pressure test. State the preserved/generalized invariant in the commit. Require correctness over development speed unless explicit prototype/fastest/throwaway. Special case: explicit user-approved boundary; broader cases left untouched with verified/out-of-scope rationale. Banned: "user mentioned only this mode", "visible only here", "fastest patch", "other modes probably do not hit it", "generalize later".
- **Directory-level entity separation:** organize source directories by primary entity type + ownership/lifecycle contract, not extension/language/name convenience. Before add/move, classify (1) owner/invoker lifecycle and (2) input/output contract, side effects, gate semantics; group only when both match or as platform variants of one command. Otherwise use an existing canonical directory, typed subdirectory, or recorded repo-local exception; no catch-all. Build output, caches, `__pycache__`, gitignored `.scratch/`, and generated outputs are out of scope. Full narrative + grandfathered exceptions: `shared/references/repository-source-hygiene.md`.
- **Trash hygiene and archival:** within the admitted change surface and subject to `Worktree safety`, keep working directories free of obsolete files. Delete replaced/superseded/dead files; if that erases recoverable history not yet in version control or session logs, move them to a clearly-named archival path (`archive/`, `legacy/`, `<dir>/_archive/`) with a one-line breadcrumb. Do not leave half-finished alternatives, dead helpers, stale docs, or "TODO: remove later" beside live code.
