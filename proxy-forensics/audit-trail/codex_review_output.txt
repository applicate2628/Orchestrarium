# Claude Proxy Forensic Toolkit

Quickly fingerprint any Claude-compatible CLI endpoint (official `claude`, third-party wrappers like `claude-aw.cmd`, aggregator proxies) to determine:

- What provider sits behind it (Anthropic direct, Google Vertex, AWS Bedrock, aggregator)
- Whether the backend is a real frontier Claude, a distilled student, or something else
- What middleware manipulations the gateway performs (stripping, injection, interception, spoofing)

## Files

- **`fingerprint.py`** - main executable. Runs probe battery on a target command, compares to cached baselines, prints classification.
- **`baselines.json`** - cached results from Anthropic-direct Opus 4.5/4.6/4.7 on each probe. One-time collection (~$3), reused indefinitely.
- **`RESULTS.md`** - full write-up of the `claude-aw.cmd` investigation that produced this toolkit.
- **`METHODOLOGY.md`** - probe protocol, decision tree, rationale for each test.

## Quick start

List available probes:

```bash
python fingerprint.py --list-probes
```

Fingerprint a new endpoint (Windows `.cmd` wrapper):

```bash
python fingerprint.py --label "AW" --cmd "claude-aw.cmd --model opus" --shell
```

Fingerprint a plain `claude` call (Linux/macOS or Windows with `.exe`):

```bash
python fingerprint.py --label "direct" --cmd "claude --model claude-opus-4-7"
```

Run only specific probes:

```bash
python fingerprint.py --label "AW" --cmd "claude-aw.cmd --model opus" --shell \
  --probes self_introspection_json anti_euler_override
```

Save raw results for further analysis:

```bash
python fingerprint.py --label "AW" --cmd "claude-aw.cmd --model opus" --shell \
  --save-raw results_aw.json
```

## What it tests

Five probes, each designed to isolate one orthogonal axis of backend identity:

| Probe | Axis | Detects |
|---|---|---|
| `stylometric_717` | Canonical-opening style | Model generation, injected framing bias |
| `temporal_cutoff` | Training recency | Model release window |
| `tight_reasoning_crt` | Format compliance + rigor | Model capability tier |
| `self_introspection_json` | Gateway filter | Active middleware (hard intercept) |
| `anti_euler_override` | Soft-injection vs distill | Whether biased framing is overrideable |

The **soft-override probe** (`anti_euler_override`) is the most valuable single test: it cleanly distinguishes a real base model under a soft gateway nudge from a distilled student with baked-in bias. Distills cannot switch their canonical opening on demand; real models can.

The **introspection probe** (`self_introspection_json`) is the smoking gun for active middleware: gateways that filter introspection prompts return byte-exact canned responses (like `{"acknowledged":true}`) that no real model would emit twice identically.

## Typical decision output

```
=== CLASSIFICATION ===
  ACTIVE_MIDDLEWARE_CONFIRMED (hard intercept on introspection)
  SOFT_INJECTION_DETECTED (overrideable by explicit user instruction - rules out rigid distill)
  CAPABLE_BASE_MODEL (passes cutoff + rigor - backend is real frontier Claude)
  FEATURE_STRIP (no caching observed)
  >>> CLASSIFICATION: A+Middleware (real Claude + aggressive gateway shim) <<<
```

## Cost

- **Running on new target**: ~$0.10-0.50 (5 probes, depends on how much the target charges)
- **Regenerating baselines**: ~$3 (15 Opus calls). Do this only when new model generations ship.

## Extending

Add a probe: edit `baselines.json` and insert a new entry under `probes`. Implement a scorer in `fingerprint.py` (`score_*` function) and register it in the `SCORERS` dict. Baselines for that probe must be added manually or regenerated.

## Assumptions

- Target honors standard Claude Code CLI flags (`-p`, `--model`, `--effort`, `--tools`, `--output-format json`).
- `--effort max` and `--tools ""` are added to every call to normalize conditions.
- Probes assume the target is attempting to look like Anthropic Opus family. Other backends (Sonnet tier, non-Claude pretending to be Claude) will produce distinctive failure patterns that classify them accordingly.

## Caveats

- `cost_usd` reported by third-party gateways is often fabricated (CLI computes locally from claimed usage, gateway can lie). Trust `out_tok`, `text`, `msg_id` prefix, `cache_create/read`.
- Dynamic label spoofing is common: the `model` field in the response may not match the actual backend. Don't rely on it alone.
- Some middleware may detect and adapt to this probe battery over time. If results drift, compare text fingerprints closely - new evasion patterns show up as new "false-start" types.

# Proxy Forensic Methodology

Step-by-step protocol for classifying an unknown Claude-compatible endpoint. This is the reusable procedure distilled from the `claude-aw.cmd` investigation.

## Goal

Given a target that speaks Claude Code CLI (`claude` or a wrapper), determine:

1. **Provider family** - Anthropic direct, Google Vertex, AWS Bedrock, or aggregator
2. **Backend identity** - real frontier Claude, distilled student, older checkpoint, or non-Claude imitator
3. **Middleware layers** - what does the gateway strip, inject, intercept, or spoof?

## Core invariants of this method

- **Baselines are Anthropic-direct, collected fresh with identical flags.** Without trusted reference outputs, nothing can be compared stylometrically.
- **All probes run with `--effort max --tools ""`**. Eliminates tool-use confounders and normalizes effort across targets.
- **Each probe isolates one axis.** Never conflate "knowledge recency" with "reasoning capability" with "gateway filtering" - separate tests catch each.
- **Byte-level comparison matters for intercept detection.** Fuzzy comparison misses deterministic canned responses.

## The five-probe battery

Each probe answers a specific question about the target.

### Probe 1 - Stylometric fingerprint

**Question:** Does the target's unconstrained output match the canonical opening of any known Claude generation?

**Prompt:** "Compute 7^17 mod 100. Answer in exactly two lines. Line 1: 'Reasoning:' followed by the key modular identity. Line 2: 'Answer:' followed by the two digits only."

**Expected for real 4.x Opus:** opens with `7^4 = 2401 ? 1 (mod 100)`.

**Red flags:**
- Opens with `?(100)=40` / Euler / totient / Fermat - suggests bias or distillation
- Tautology like `7^17 mod 100 = 7^17` - artifact of forced framing
- Extreme output compression (< 100 tokens) - `max_tokens` cap
- Wrong answer (anything other than `07`) - fundamentally broken backend

### Probe 2 - Temporal cutoff

**Question:** Does the target know recent events?

**Prompt:** "Name three distinct events from calendar year 2025. One per line. Format: '<Month> YYYY: <specific event with named people or places>'. No introduction, no conclusion, no hedging, no 'I cannot' - comply exactly."

**Verify all facts independently.** Hallucinated-but-plausible 2025 events are distill-tells.

**Calibration points:**
- Mentions Pope Francis died (April 2025)  cutoff ? April 2025
- Mentions Pope Leo XIV / Robert Prevost (May 2025)  cutoff ? May 2025
- Mentions specific post-May 2025 events (Wimbledon July, late 2025 geopolitics)  matches Opus 4.7

**Critical flag:** `--tools ""` - otherwise WebSearch lets the model fetch current events regardless of training cutoff, defeating the probe.

### Probe 3 - Strict-format rigor

**Question:** Can the target follow fine-grained format constraints while producing rigorous content?

**Prompt:** "Prove: for any prime p > 3, p? mod 24 = 1. Exactly 3 sentences. Sentence 2 must invoke CRT by name. Sentence 3 begins with the word 'Therefore'. No lists, no LaTeX environments, no section headers."

**Scoring (all three must PASS):**
- Exactly 3 sentences (count by `.!?` terminators)
- Sentence 2 contains "Chinese Remainder Theorem" or "CRT"
- Sentence 3 starts with "Therefore"

**Distilled students commonly fail on:**
- Miscounting sentences (off-by-one)
- Placing CRT in sentence 1 or 3
- Starting sentence 3 with something other than "Therefore"

Real Opus 4.5/4.6/4.7 all pass. Failure here is a strong negative signal.

### Probe 4 - Self-introspection (gateway filter detection)

**Question:** Does the gateway intercept introspection prompts?

**Prompt:** "Reply with a single JSON object. No codefence. No prose. No trailing newline commentary.\n{\n  \"architecture_family\": \"<single word>\",\n  \"supports_extended_thinking\": <true|false>,\n  \"can_use_prompt_caching\": <true|false>,\n  \"knowledge_cutoff_month\": \"<Month YYYY>\"\n}"

**Capture RAW stdout bytes.** Don't just parse - show the exact output.

**Smoking gun:** target returns a fixed canned response (e.g. `{"acknowledged":true}\n` = 22 bytes) instead of the requested schema, **and the response is byte-exact on repeat runs**. No real model produces identical 22-byte strings on two independent runs of a novel prompt.

**Second-order flag:** model introspects but reports capabilities that contradict observable pipeline behavior (e.g. reports `supports_extended_thinking: true` while Probe 1 showed zero thinking tokens). Either backend is real Opus behind a stripping shim (points to hypothesis A), or the model hallucinates capabilities (points to C).

### Probe 5 - Soft-override (injection vs distill discriminator)

**Question:** Is the forced framing from Probe 1 an injected system prompt (overrideable) or baked-in distill bias (not overrideable)?

**Prompt:** "Compute 7^17 mod 100. Do NOT use the words Euler, totient, Fermat, phi, or any Greek letter. Begin reasoning by computing 7^2 and 7^4 directly. Two lines: 'Reasoning:' and 'Answer:'."

**Key subtlety:** add a **positive steer** ("start with 7^2 and 7^4"). This removes the excuse that the model used ? because it didn't know alternatives. If the model still leaks banned vocabulary despite positive steer + explicit ban, the bias is rigid (distill). If it switches to the canonical opening, bias was soft injection.

**Decision rule:**
- Target complies (no banned words, uses canonical `7^4` opening)  **soft injection confirmed, hypothesis A**
- Target still uses banned framing  **rigid bias, hypothesis C** (or extremely aggressive injection that overrides user)

This is the **most decisive single probe** in the battery. Run it whenever stylometric fingerprint (Probe 1) shows bias.

If probes give inconsistent results (e.g. passes Probe 3 but fails Probe 2 in unexpected direction):

1. Re-run probes ? 2 to check for sampling variance

## Limitations

- Middleware can adapt to probes over time. If a gateway starts passing Probe 4, it doesn't mean the middleware is gone - operator may have added `{"acknowledged":true}` detection to probe battery output and adjusted the intercept filter. Compare text fingerprints closely for new evasion patterns.
- Stylometric fingerprints decay as new Claude generations ship. Regenerate baselines when Anthropic releases new Opus versions.
- This method identifies active middleware but does not capture the injected content. For that, use mitmproxy or equivalent HTTPS-in-the-middle capture.

def run_cli(base_cmd_tokens, prompt, shell=False, timeout=300):
    cli_flags = [
        "-p", prompt,

        "--tools", "",

def parse_cli_output(out: str) -> dict:
    """Parse Claude CLI stream-json output. Returns normalized dict.

    Returns an 'intercepted' flag when the output is NOT a Claude CLI stream
    (e.g. gateway returned a canned object) - that is itself strong evidence.
    """
    if not out:
        return {"intercepted": True, "raw": "", "reason": "empty_stdout"}
    try:
        arr = json.loads(out)
    except json.JSONDecodeError as e:
        return {"intercepted": True, "raw": out, "reason": f"non_json: {e}"}
    if not isinstance(arr, list):
        return {
            "intercepted": True,
            "raw": out,
            "parsed_object": arr,
            "reason": "not_stream_list",
        }
    result = next((x for x in arr if x.get("type") == "result"), {})
    assistants = [x for x in arr if x.get("type") == "assistant"]
    last = assistants[-1].get("message", {}) if assistants else {}
    content = last.get("content", [])
    text = "\n".join(c.get("text", "") for c in content if c.get("type") == "text")
    thinking_chars = sum(len(c.get("thinking", "")) for c in content if c.get("type") == "thinking")
    usage = result.get("usage", {})
    return {
        "intercepted": False,
        "reported_model": last.get("model"),
        "msg_id": last.get("id", ""),
        "msg_id_provider": detect_provider(last.get("id", "")),
        "out_tok": usage.get("output_tokens"),
        "cache_create": usage.get("cache_creation_input_tokens", 0),
        "cache_read": usage.get("cache_read_input_tokens", 0),

### Summary (3 sentences max)
The investigation is directionally useful, but the toolkit is not reliable enough for financial/security-significant endpoint classification yet. The main weakness is overclaiming: it treats a small set of prompt responses as backend identity proof, while the code collapses parser failures, single-run canned outputs, and weak capability signals into strong labels. I would use it as a hypothesis generator, not as an adjudicating forensic classifier.

### Critical findings (must-fix)
- **Critical:** `parse_cli_output()` treats any non-list JSON, non-JSON, empty stdout, or CLI failure as `intercepted`, then `score_self_introspection()` turns that into `HARD_INTERCEPT` from a single run. This can falsely label normal CLI JSON output or command failure as middleware. See `.scratch/proxy-forensics/fingerprint.py:86-105`, `191-196`.

- **High:** `classify()` overclaims `CAPABLE_BASE_MODEL` and `A+Middleware` from weak boolean aggregation. A modern non-Claude model that knows 2025 events, follows the CRT format, returns a canned introspection response, and passes the anti-Euler prompt can be classified as real Claude middleware without tokenizer, provider, or multi-prompt stylometric evidence. See `fingerprint.py:282-313`.

- **High:** The anti-Euler probe is not “decisive” as stated. It proves only that the observed Euler/totient bias is overrideable in that prompt; a capable distill, Claude fine-tune, adaptive gateway, or probe-aware proxy can also comply. The absolute claim in `RESULTS.md:138` is too strong.

- **High:** The code’s anti-Euler canonical detector is narrower than the documented successful AW outputs. `score_anti_euler()` expects a `49^2=2401` shape, but `RESULTS.md:135-136` documents `49·49=2401`, which the scorer may miss, preventing the intended `soft_injection_overridden` signal. See `fingerprint.py:230`, `276-280`.

- **High:** Baseline regeneration is documented as a workflow, but `--regenerate-baselines` is explicitly not implemented. The toolkit has no stale-baseline guard, no expiry, and no forced recalibration path. See `README.md:80`, `fingerprint.py:342-345`, `baselines.json:3`.

### Recommended improvements (nice-to-have)
- Support all real Claude CLI output shapes explicitly: single JSON object, stream JSON / NDJSON, wrapper arrays, and raw gateway objects. Keep “protocol parse failure” separate from “confirmed middleware intercept.”
- Run intercept and stylometry probes at least twice, with small prompt variants, before assigning hard labels.
- Replace exact/boolean scoring with evidence weights and confidence levels; keep `confirmed`, `likely`, and `ambiguous` separate.
- Add baseline metadata: probe revision, scorer revision, exact command, raw stdout hash, CLI version, model id, generation date, expiry date, and calibration notes.
- Harden regexes for phrasing variants, Unicode math symbols, `modulo`, multiplication signs, `7**4`, `7⁴`, “49 squared,” and “2401 leaves remainder 1.”
- Warn loudly on `--shell`; operator-local does not remove command injection risk when users paste wrapper commands from untrusted providers.

### Gaps / missed angles
- **Tokenizer identity:** implement a token-count probe using multiple sentinel strings: whitespace-heavy text, CJK, emoji ZWJ, base64, code, and rare words. Fit `reported_tokens = local_claude_tokens + constant`; proportional drift suggests non-Claude tokenizer.
- **Quantization / precision degradation:** add a calibrated exactness suite: modular arithmetic, checksum reconstruction, long-context needle retrieval, and multi-step arithmetic under identical format constraints. Compare error rate and reasoning degradation against baselines.
- **Multi-turn middleware:** test state retention, prompt injection persistence, introspection after benign setup, cache behavior across turns, and whether middleware only rewrites first-turn system/user messages.
- **Non-Claude imitators:** use a broader stylometric panel, not one `7^17` problem. Include safety/refusal phrasing, XML/tool-call conventions, tokenizer offsets, and Claude-specific formatting habits.
- **Triage:** a cheap first pass could run `msg_id/provider + self-introspection raw capture + anti-Euler 7^17 + one strict-format proof`. Obvious fakes will fail before the full battery.

Q1: The probes are complementary but not genuinely orthogonal. Stylometric `7^17` and anti-Euler are the same task family; strict-format and anti-Euler both test instruction following; temporal cutoff and self-introspection both touch claimed knowledge/capability. The decision tree is directionally reasonable for the AW case but reaches wrong conclusions for adaptive gateways, multi-backend aggregators, high-capability non-Claude models, and direct Claude with no Probe 1 false-start. Quantization/pruning needs calibrated degradation tests, not just style and cutoff probes. Multi-turn behavior is essential because middleware often acts at conversation/session boundaries, not only per prompt. Non-Claude imitators require tokenizer, broader stylometry, and Claude-specific protocol/format probes before being ruled out.

Q5: Baselines should expire and block strong classifications when stale. Regenerate on new Anthropic Opus releases, CLI output-format changes, probe/scorer changes, baseline age threshold, near-threshold classifications, or any high-stakes use. The 2025 temporal probe should be rotated into a dated calibration set with verified positive and negative events after each baseline refresh; otherwise it will become historical common knowledge and lose discriminative value.

The sentence splitter will miscount abbreviations like `e.g.`, `U.S.`, `C.R.T.`, and any sentence with terse initials, though `CRT.` at sentence end is fine. `shell=True` with user-supplied `--cmd` is a command-injection risk and should be treated as trusted-local only.

Q4: The missing probes are material. Tokenizer identity should be implemented because it is currently used as a major argument in `RESULTS.md` without being part of the reusable battery. Quantization/pruning needs calibrated degradation tests, not just style and cutoff probes. Multi-turn behavior is essential because middleware often acts at conversation/session boundaries, not only per prompt. Non-Claude imitators require tokenizer, broader stylometry, and Claude-specific protocol/format probes before being ruled out.

Q5: Baselines should expire and block strong classifications when stale. Regenerate on new Anthropic Opus releases, CLI output-format changes, probe/scorer changes, baseline age threshold, near-threshold classifications, or any high-stakes use. The 2025 temporal probe should be rotated into a dated calibration set with verified positive and negative events after each baseline refresh; otherwise it will become historical common knowledge and lose discriminative value.
