### Answers to 5 questions

1. **Full matrix necessary?**  
   Not scientifically mandatory for a hypothesis generator, but necessary if the claim is “calibrated across all available models and efforts.” Otherwise the honest stamp is narrower: “validated on Opus 4.7 max; other lanes unvalidated.”

### Summary (2 sentences)
Single-model `claude-opus-4-7 --effort max` validation is not enough to stamp a multi-model v0.6 toolkit as stable. Full matrix is more than a hypothesis-generator strictly needs, but at ~$15 it is the right release discipline if the toolkit now exposes model/effort as a supported calibration surface.

### Answers to 5 questions

1. **Full matrix necessary?**  
   Not scientifically mandatory for a hypothesis generator, but necessary if the claim is “calibrated across all available models and efforts.” Otherwise the honest stamp is narrower: “validated on Opus 4.7 max; other lanes unvalidated.”

2. **Is effort calibration redundant if suspects are forced to `max`?**  
   Partly, for the default suspect path. But not fully: the CLI silently degrades some efforts, endpoints may ignore or reinterpret effort, and `--probe-effort` is now a user-visible dimension. Effort calibration also tests cache keys, scorer normalization, thresholds, parser robustness, and requested-vs-effective effort labeling.

3. **Minimum for `v0.6 stable`:**  
   I would require live E2E validation on every supported model at its canonical effective effort, plus all-effort validation on at least one Opus model, plus explicit degradation checks for Sonnet/Haiku `xhigh`/`max`. Anything less should be stamped as “default-lane stable,” not “multi-model stable.”

4. **Combo-specific bugs single Opus max can miss:**  
   Model alias/date-stamp normalization bugs; baseline cache keyed by model but not effort; `--probe-effort` ignored; CLI degradation mislabeled as real `xhigh`/`max`; smaller/low-effort models breaking output schema; confidence thresholds overfitting Opus; timeout/token/cost path issues; false positives caused by effort-induced style shifts.

5. **Practical recommendation:**  
   Run the full matrix now. Record both `requested_effort` and `effective_effort`, and mark degraded Sonnet/Haiku `xhigh`/`max` lanes as degradation checks, not independent capability.

### Recommended scope

Run full model × effort calibration for v0.6, with 5 probes per combination and at least one repeat on default/canonical lanes. Keep the default scorer normalization at `max`, but make the calibration report explicit about which lanes are default-supported, which are exploratory, and which are CLI-degraded aliases.
