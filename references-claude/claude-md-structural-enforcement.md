# Claude Markdown Structural Enforcement Detail

This provider-local maintainer reference owns the current exhaustive Claude Code hook contract; it is documentation source, not installed runtime content.

The always-loaded `src.claude/CLAUDE.md` retains the operative structural-enforcement rules and points here for exhaustive hook and installer detail.

`check-git-push-gate-runner.py` is the registered minimal entry point. It imports only the fixed regular siblings `hook_common.py` and `check-git-push-gate.py`; the latter remains the single policy owner. Any load or delegation failure returns a constant deny without raw detail. Normal warm-cache launches use Python's standard import cache instead of executing the large policy source as `__main__`. Because the registered command identity changes, the next Codex install requires interactive trust review.

The pack ships thirteen entries: nine structural hooks — four blocking-enforcement (bugfix-discipline, git-push-gate, passive-polling, MCP force) and five warn-only audits (machine-local-path, no-trash-in-repo, stale-relation-residue, repository-orientation, typed-routing) — plus four reminder/context hooks. They are backstops; they do not replace the text rules above.
The three `SessionStart` entries (`mcp-usage-reminder`, `agents-mode-reminder`, `check-scratch-valuables`) run on startup/resume/clear/compact; `turn-anchor-reminder` runs at every `UserPromptSubmit`. Shared reminders emit structured `hookSpecificOutput` context; all four are fail-open. MCP usage remains generic and discovers the connected server surface instead of shipping a machine-local list.
`agents-mode-reminder` consumes `agents_mode_runtime.resolve_scalar`, the single Claude scalar-precedence owner, and emits only for `delegationMode: force|auto`; manual or unresolved stays silent. `check-scratch-valuables` is read-only and reports valuable `.scratch/` content not recoverable from Git. `turn-anchor-reminder` re-anchors continuation and early Lead delegation at every user turn. Dispatched prompts should allow relevant MCP use within their role, scope, and safety limits.

**PreToolUse bugfix-discipline hook.** `check-bugfix-discipline.py` catches the most common pre-fix discipline violation: the model is about to make a code-mutating tool call (`Edit`/`Write`/`NotebookEdit`/`apply_patch`) in response to a user message that contains a bug-report or change-request signal (e.g. `fix`, `change`, `broken`, `не работает`, `исправь`, `пофикси`, `поменяй`, traceback, `Error:`), but it did NOT first invoke `/agents-bugfix` or otherwise capture diagnostic data. The hook reads the PreToolUse envelope's `transcript_path`, parses the recent transcript tail, and:

- If the envelope carries `agent_id` (a subagent context) → exit 0 (allow; the dispatching main conversation owns the diagnostic discipline at the dispatch decision, and a subagent must never be blocked).
- If the write target path is under `.reports/`, `.scratch/`, `.plans/`, `work-items/`, or `docs/` (matched as a `/`-bounded segment, so `src/mydocs/x.py` is NOT exempt) → exit 0 (allow; a doc/report/scratch/plan/task-memory write is never the CODE fix this guard targets — verified on a real transcript where the guard fired legitimately on a `.reports/` memo write under a bug-fix-review prompt with no prose marker).
- If the last user message contains no bug-trigger phrase → exit 0 (allow; not a bug context).
- If the last user message contains the override marker `[skip-bugfix-discipline]` → exit 0 (allow; user explicitly opted out).
- If the current turn (everything after the last user message) shows discipline signals (`/agents-bugfix` invocation, `agents-bugfix` skill load, text containing `diagnostic`/`hypothesis`/`reproducing`/`VERIFIED:`) → exit 0 (allow; model is following the flow).
- Otherwise → emit a structured `permissionDecision: "deny"` JSON payload telling the model exactly how to comply (invoke skill, capture diagnostic data, or use override marker).

**PreToolUse git-push publication-gate hook.** `check-git-push-gate.py` is the structural backstop for the publication-safety rule "human review before `git push` must include a leak-check of staged changes" — previously prose-only while lower-stakes edit/stop moments had blocking hooks. Registered on the `Bash` matcher, each live or transcript command retains its actual tool identity, resolves dialect once, and builds one immutable effective-publication projection. A declarative seven-row wrapper registry and one argument-vector state machine own exact `eval`, `env`, `command`, `exec`, `sudo`, POSIX-shell, and PowerShell-host children. Assignments, option tokens and attached/detached values, terminators, modes, operands, and suffixes stay typed terminal participants; malformed, incomplete, unsupported, or unresolved publication-capable participants remain non-authorizing candidates at every nesting depth and cannot yield an exact-empty graph. Direct child argument vectors are never joined/reparsed. Complete proven heredoc/here-string bodies are data; uncertain regions retain conservative push candidates. In an unquoted open PowerShell token, backtick plus line feed remains token content, while backtick plus carriage-return/line-feed is an executable boundary on both supported PowerShell targets. The test-only in-process harness is cooperative evidence, not publication authority. Arbitrary same-process mutation defeats harness observation and may run arbitrary caller code; the only proven invariant is that unchanged shipped source contains no external adapter or launcher, and its cooperative result has zero production/publication consumers. One lifecycle owner keeps exact typed preparation, one-use run binding, six actual deadline/cancellation phases, canonical bounded capture, and reverse-order cleanup; clean close purges all member/state/capability/resource records, while cleanup failure retains one bounded retry record until a successful retry purges it. Each of the six external owners calls the literal unavailable factory once and stops at `ORACLE-AUTHORITY-UNAVAILABLE`, adapter/external `0/0`; the shipped harness contains no external adapter, launcher, discovery, or fallback. Only exactly one unambiguous standalone positive long `--dry-run` publication with no sibling receives the fast allow. It then:

- If the envelope carries `agent_id` (a subagent context) → exit 0 (allow; mirrors the bugfix guard — a subagent cannot inject the user-side override into the main transcript. Governance still forbids delegating a push to a subagent to dodge review).
- If the LAST GENUINE USER MESSAGE contains the per-turn override `[approve-publication]` → allow. Unlike `[skip-bugfix-discipline]`, this marker is honored ONLY from the user's own message — never from assistant prose, tool calls, or tool output — because quoted or injected content must not approve a publication.
- If the last genuine user message contains an explicit push instruction and the push is one admissible solitary direct ambient invocation, the gate freezes remote/destination/source/current-`HEAD`, captures and directly executes the verified `hook_common.py` + machine-path-classifier + canonical scanner closure, and allows only the exact pending invocation's bounded, reaped, non-empty version-2 result with matching receipt tip. Transcript/manual, default/tracked, path, legacy/v1, zero-commit, malformed, finding, refusal, correlation, provenance, execution, drift, or reused results deny.
- Otherwise → emit a structured `permissionDecision: "deny"` payload with exact compliance instructions (report readiness and ask the user to approve with the marker; or, when the push was already instructed, run the safety scan first this turn and retry; or use `--dry-run`).

It is a BACKSTOP, not a guarantee: exact literal wrapper children remain visible, including multi-argument `eval`. Opaque wrapper-file contents, runtime-generated expansion absent from typed literal input, aliases/functions resolved only at runtime, repository identity, remote URL/server freshness, and Git metadata outside selected commit messages and current-tip blobs are not covered. A detected non-dry push or conservative candidate without an authorizing gate-owned result denies; malformed envelopes and definite non-push text retain their explicit fail-open posture. Human review plus a final leak-check remain mandatory before any push.

**Stop passive-polling hook.** `check-passive-polling-stop.py` catches a different failure: the model is about to end its turn by saying it is waiting for an async external source (bot/review/CI/job/notification/reply) without a relevant current-turn state check. The hook reads `last_assistant_message` directly from the Stop envelope, exits immediately when `stop_hook_active=true`, and parses the transcript only after a passive-polling phrase is detected. It allows user handoffs such as `waiting for your response` / `жду твоего подтверждения`, allows the per-stop override marker `[acknowledge-passive-stop]`, and otherwise requires a relevant probe in the current turn: time/status commands (`date`, `Get-Date`, `gh pr view`, `gh run list`, `gh api`, `curl`), process/task output, or reads of output/log/task files. If no relevant probe is present, it emits top-level `{"decision":"block","reason":"..."}` telling the model to check state now, use the override for a real handoff, or invoke a concrete tool like `Bash: gh pr view`.



**Five PreToolUse audit hooks (warn-only).** `check-machine-local-path.py` warns when a machine-local absolute path (a concrete user home or workstation dev root; placeholders like `<you>`, `%USERPROFILE%`, `${CLAUDE_PROJECT_DIR}` are allowed) is written into a non-`.scratch/` file. `check-no-trash-in-repo.py` (the stray-artifact guard — filename and install-marker retained for install continuity; a rename to `check-stray-artifact` is a tracked follow-up) warns on every confidently parsed `git worktree add` except one add whose command ends with the exact `# orchestrarium:requested-isolation-worktree` marker required by the installed parallel-isolation protocol; missing, near-match, quoted, reused, or batch markers do not suppress the audit. `git worktree list/remove/prune`, `git add` (not `git worktree add`), `git` inside a quoted string, and non-git commands never warn; the parser is shell-aware (shlex tokenization, command-position tracking across `&&`/`;`/`|`/`(`, env-assignment-prefix and git-global-option skipping) and fails open on any tokenizer error. This replaced a name-based version that warned only on new dirs named `kosyaks`/`mistake-log` — useless, because those are the *user's* personal-process vocabulary, not names the *agent* (the actor a PreToolUse hook guards) ever creates, so it never fired; the real reported problem was the agent creating stray artifacts, chiefly unrequested worktrees, so the guard now keys on the OPERATION, not a name. Deferred: the Claude `Agent` tool's `isolation: "worktree"` form (needs a captured PreToolUse envelope to confirm the field shape). Dropped: outside-repo writes (a static allow-list false-positive-floods on legitimate installs/temp/global-config/memory writes) and arbitrary in-repo trash (no reliable non-name signal — that stays governance). Both read their own call's `tool_input` (not session context) and ALWAYS allow the tool call — AUDIT mode. On a hit each delivers its warning to the MODEL via `hookSpecificOutput.additionalContext` on stdout and exits 0 (`hook_common.emit_advisory`), replacing the stderr-plus-exit-1 form this pack shipped before: measured this session on both target runtimes, that form reached NOBODY — a non-blocking exit 1's stderr lands in Claude Code 2.1.220's transcript record but stays invisible to the model, and on Codex CLI 0.145.0 the non-2-exit branch never even copies stderr to begin with. `emit_advisory` reads the firing event's own `hookEventName` off the incoming envelope first and uses it verbatim; a `hookEventName` that does not match the event that actually fired makes Claude Code silently discard the entire `hookSpecificOutput` payload, so a caller must never hardcode an event name that could drift from its registration. A clean check emits nothing and also exits 0. Promotion to a blocking `deny` (exit 2) remains a separate reviewed step once the false-positive rate is measured. Both fail open — a wrapper-level or internal error emits nothing and exits 0, so a hook malfunction can never masquerade as a real hit. `check-stale-relation-residue.py` is the structural backstop for architecture law C6 ("a superseding change leaves only the correct current state; stale-relation residue is erased"): it warns when an `Edit`/`Write` ADDS a stale-relation residue phrase — fixed-vocabulary markers that almost always assert an OBSOLETE relationship a completed rename / merge / deprecation / move / fix should have erased (`deprecated alias`, `former alias` / `former name`, `now-retired ... kept as a historical example`, `(was X)` / `(formerly X)` / `(previously X)` parentheticals, `misregistered as`, `X -> Y alias`, `this is wrong, the correct is Y`) — into a LIVE-tree file. It cannot run C6's full change-specific old-name grep (the hook does not know the old name), so it keys on those operation-independent residue phrases instead. The STALE-vs-LIVE discriminator is review-bound — a real dependency, a deliberate split, or a current `X vs Y` comparison uses some of the same words — so this is WARN-only; it exempts the targets where recording a superseded relation IS legitimate provenance: decision/closure/task-memory registries (`work-items/`), changelogs / release notes (`RELEASE_NOTES`, `CHANGELOG`, `HISTORY`), archival trees (`/archive/`, `/legacy/`, `_archive`), the local scratch area (`.scratch/`), and git internals (`.git/`). It reads its own call's `tool_input`, delivers a hit to the model via the same `hookSpecificOutput.additionalContext` stdout channel, ALWAYS allows, exits 0 on both a hit and a clean check (never 2), and fails open — same AUDIT contract as the other two.

The no-trash guard has four closed, command-derived triggers: (1) the unrequested `git worktree add` shape above; (2) a mangled Windows redirect target such as `> r:Tempxbuild.log`, where a drive-letter prefix has no path separator; (3) a build/log artifact redirected to a bare filename such as `> build.log` or `> probe.obj`; and (4) an `ifx`/`ifort`/`icx`/`gfortran`/`cl`/`gcc` compile with a source operand but no output-directing flag. Triggers (3) and (4) apply only when `cwd/.git` confirms that the process working directory is the repository root and the command contains no `cd`, `pushd`, or `popd`; an explicit directory change makes the destination undecidable and therefore produces no warning. Redirect targets are classified from the raw command text so POSIX tokenization cannot erase Windows backslashes. These additions do not revive the rejected open-ended outside-repository or arbitrary-trash checks.

**Repository-orientation audit.** `check-repository-orientation.py` warns before a risky repository mutation or repository-local run/build/test when assistant-authored prose after the last genuine user task lacks exactly one valid `REPOSITORY ORIENTATION:` record. It validates the five required fields, a `path:line` citation, non-conflict status, and scope ancestry; skips discovery-only commands, local artifact writes, and subagent envelopes; and emits an extra warning for `archive`, `deprecated`, `superseded`, or `frozen` path segments unless the matching non-live status and explicit user-approved historical scope are stated. It never scans repository prose or treats deprecation words as canonical-status evidence. It delivers a hit to the model via `hookSpecificOutput.additionalContext` on stdout, ALWAYS allows the tool call, and fails open; a hit and a clean check both exit 0 — the same delivery contract as its four sibling audits, so the warning reaches the model directly instead of landing only in a transcript notice the model never reads.

**MCP-force binding.** `check-mcp-momentum.py` consumes the shared source-navigation classifier and configured code-intelligence server names. Claude `mcpMode: auto` and every envelope carrying `agent_id` remain advisory through `hookSpecificOutput.additionalContext`. A root Claude conversation in effective `mcpMode: force` denies every qualifying search with structured `permissionDecision: deny` and `[MCP-FORCE-1]`; an earlier MCP call grants no later search credit. Exact `[approve-mcp-fallback:v1]` in the bounded host-projected `user`-role record allows one recovery turn. Assistant/tool text and registered injected spans cannot mint it, but this projection is not authenticated authorization and a forged host-shaped user JSONL record can satisfy it. Missing servers and unresolved modes allow with stable diagnostics. The adapter is fail-open on internal error and is registered from `agents/scripts/` on `Grep|Bash|PowerShell|shell_command|exec_command`.

**Typed-routing audit.** `check-typed-routing.py` (Claude-only) warns when the orchestrator dispatches the built-in catch-all `subagent_type: general-purpose` for work that looks like typed specialist work, so the routing smell surfaces at the one moment it is observable — the dispatch decision itself. It fires only when all of: the envelope `tool_name` is the subagent-dispatch tool; `tool_input.subagent_type` casefolds to a member of `CATCH_ALL_TYPES` (`general-purpose` initially — `Explore`/setup agents are deliberately excluded as legitimate read-only agents); the dispatch prompt/description carries a specialist-work signal (`implement|fix|build|refactor|.ps1|.py|.ts|toolchain|installer|hook|review|audit|security|perform|design|architecture|migrat`, case-insensitive, mirroring mcp-momentum's "only fire when it looks like the target class" narrowing); and there is no `agent_id` (skip subagent contexts — a nested dispatch runs its own policy). On a hit it delivers one `[typed-routing AUDIT]` message to the model via `hookSpecificOutput.additionalContext` on stdout, pointing at the typed roster (`.claude/agents/*.md` — e.g. toolchain-engineer / platform-engineer for `.ps1`/install work, an engineer role for code, a reviewer role for review), and exits 0 (never 2); a clean check also exits 0. It ALWAYS allows the tool call (warn-only needs no override marker — the model proceeds regardless) and fails open on any internal error. The dispatch-tool shape was Phase-0 captured from real session transcripts: `tool_name == "Agent"` (NOT `Task`), with `subagent_type` in `tool_input`; it keys on those NAMED constants and is INERT (exit 0, silent) if either is absent, so a future rename makes the hook fire-nothing rather than a false block. It is Claude-only — Codex CLI has no analogous subagent-dispatch tool, so there is no Codex mirror and the Codex pack's structural-hook count is unchanged. Registered on the `Agent` dispatch-tool matcher.

**The installer auto-installs all thirteen hook entries by default.** Both `scripts/install-claude.sh --global` and `scripts/install-claude.sh --target <project>` merge the `PreToolUse` entries (bugfix-discipline + git-push-gate on a `Bash` matcher + machine-local-path + no-trash-in-repo, the last with a `Bash`-inclusive matcher so it sees the `git worktree add` command, + stale-relation-residue + repository-orientation on the full edit/shell matcher + mcp-momentum on a `Grep|Bash|PowerShell|shell_command|exec_command` matcher + typed-routing on an `Agent` dispatch-tool matcher), the `Stop` entry (passive-polling), the three informational `SessionStart` entries (`mcp-usage-reminder` + `agents-mode-reminder` + `check-scratch-valuables`, all no-matcher), and the `UserPromptSubmit` entry (`turn-anchor-reminder`, also no-matcher) into `settings.json` with an idempotent JSON merge that preserves other keys and hooks. Opt out at install time with `--no-hypothesis-hook` (legacy flag name kept for back-compat) or `ORCHESTRARIUM_NO_HYPOTHESIS_HOOK=1`. Remove entries independently:

The default registration invokes the installed `.py` file directly with the absolute `sys.executable` of the Python process running the installer. Before registration mutation, the Python runtime checks every owned hook: the interpreter and `.py` target must be absolute regular files; Windows requires a non-reparse `.exe`, while POSIX requires execute permission on the interpreter. The later health gate actually launches every registered hook. The reserved native runtime requires a real native executable and fails before mutation because no native hook binaries ship. The transaction is strictly **SYNC → REGISTER → VERIFY**; `scripts/check-hook-health.py` is the hard verification gate.

## Terms and Abbreviations

- `JSON`: JavaScript Object Notation, the structured format used by hook settings and envelopes.
- `LF`: Line Feed, the newline byte format preserved in every payload.
- `MCP`: Model Context Protocol, the runtime interface used to expose connected tools and resources.
