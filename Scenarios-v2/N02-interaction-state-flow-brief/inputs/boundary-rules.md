# Boundary Rules

- Stay inside `$ux-designer` ownership. Produce one forward-looking UX structure brief.
- Do not turn the artifact into implementation tickets, widget trees, route maps, API payload
  definitions, or persistence designs.
- Do not produce review findings, severity-ranked bug lists, or accessibility audit output.
- State ladders, interruption states, return loops, and resume cues are in scope.
- Framework mechanics, backend orchestration code, and exact visual styling specs are not.
- End with one explicit status: `PASS`, `REVISE`, or `BLOCKED`.
