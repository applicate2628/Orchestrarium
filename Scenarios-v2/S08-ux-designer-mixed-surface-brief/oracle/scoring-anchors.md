# Scoring Anchors

## Strong brief

- clearly separates desktop preparation from web review and publish without leaving the handoff
  vague
- introduces a coherent cross-surface state model with explicit ownership
- restructures the return loop for changes or interruptions so the curator lands in the right place
- describes screen or surface hierarchy at the UX level and keeps implementation work out of scope
- preserves the boundary against architecture ADRs and review findings

## Partial brief

- identifies the desktop/web confusion but only fixes labels or copy
- proposes a better flow without clarifying who owns each state
- keeps the role mostly UX-focused but drifts into light implementation hints or review language

## Weak brief

- ignores one surface
- offers a bug list or audit instead of a design brief
- turns the artifact into wireframe implementation notes, route specs, or component breakdowns
- leaves state and return-loop behavior unresolved
