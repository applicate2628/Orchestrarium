# Expected UX Direction

The strongest `N01` responses converge on the same structural direction:

1. Establish one cross-surface hierarchy ladder.
   - example shape: `Current release verdict -> active blocker or reviewer ask -> owner and lane ->
     evidence freshness -> supporting metadata`
2. Give each surface a clear static emphasis model.
   - desktop should foreground active preparation and validation context
   - web should foreground review readiness and publish disposition
3. Keep shared facts named the same way across both surfaces.
   - bundle identity, lane, owner, blocker type, reviewer ask, and freshness should not require
     translation when operators switch surfaces
4. Demote routine metadata and history below the active release decision.
   - screenshots, archive notes, and passive counts should not visually outrank blockers or
     unresolved review asks
5. Solve the problem with structure first.
   - stronger grouping, hierarchy, and emphasis are required
   - color tweaks or copy edits alone are not sufficient

The exact labels may vary, but the best briefs make information priority legible before operators
start acting.
