# Boundary Rules

- Stay inside `$ux-designer` ownership. Produce one forward-looking UX structure brief.
- Do not turn the artifact into implementation tickets, widget trees, CSS token specs, route maps,
  or API payload definitions.
- Do not produce review findings, severity-ranked bug lists, or accessibility audit output.
- Static hierarchy and information structure are in scope. Low-level color values, responsive break
  points, and framework mechanics are not.
- Cross-surface naming and grouping are in scope when they clarify hierarchy.
- End with one explicit status: `PASS`, `REVISE`, or `BLOCKED`.
