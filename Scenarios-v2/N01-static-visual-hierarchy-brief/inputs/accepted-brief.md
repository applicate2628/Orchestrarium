# Accepted Brief

## Admitted problem

The release workflow already has the right broad surface split:

- desktop is for preparation, local validation, and bundle-level curation
- web is for shared review, approval context, and publish decisions

The problem is that both surfaces flatten critical information. Operators must hunt for the active
blocker, the most recent reviewer ask, the owner, and the freshness of supporting evidence.

## Protected assumptions

- The workflow must stay split across desktop and web; this is not a single-surface redesign.
- Release blockers, reviewer asks, evidence freshness, and publish readiness must remain visible on
  both surfaces, but not at the same visual weight as routine metadata.
- Bundle identity, lane, owner, and current readiness must use shared labels across both surfaces.
- The brief may restructure grouping and emphasis, but it must not prescribe implementation classes,
  routes, APIs, or storage changes.

## Success read

A strong brief gives operators one shared hierarchy ladder across both surfaces and makes the same
critical facts easy to scan without re-interpretation.
